# 结果块骨架（golden）

`ledger.py result` 的唯一合法形态。本文件与 `ledger.py` 里的 `SECTION_*` / `HINT_*` / `COLS_*` / `W_*` 常量一一对应（搜 `SECTION_SESSION` 定位，别记行号），改一处必须改另一处，并跑 `ledger.py result --check`。

输出是 **GFM markdown**：三行摘要 + 四段 `###` 小节，表格直接渲染。**不要再用代码围栏包起来**——包了会变成灰色等宽文本块，既难看又丢掉表格样式。

## 骨架

````markdown
结果 · <run-id> · <scope> · <条数> 条 · <体积>
判定 kill <n> · discard <n> · sediment <n> · blocked <n>
落地 <条目> 条目 → <文件> 文件｜已删 <n> · 待删 <n>｜待你点头后执行沉淀 / 删除

### ① 会话
*排序：sediment→kill→discard→blocked，组内体积降序*

| sid | 轮 | 判定 | 内容 | 处置 | 处置理由 |
| --- | ---: | --- | --- | --- | --- |
| <8 位> | <n> | <verdict> | <这条会话在聊什么、留下了什么> | 已删 / 待删 / 卡住 / - | <凭什么待删 / 凭什么已删> |

### ② 落点
*排序：条目数降序 → 落点名*

| 落点 | 条目 | 沉淀什么 | 文件 | 新建 | 更新 | 来源 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| <bank:项目 或 db:域/文件> | <n> | <这些条目各自的标题，`；` 分隔> | <n> | <n> | <n> | <sid8,sid8> |

### ③ 异常
*无则写「无」*

| 类型 | 对象 | 说明 |
| --- | --- | --- |
| 置顶待删 | <sid8> | isPinned=1：点头后随目标一并删，不需先取消置顶 |
| 旧判定 | <sid8> | 归档范围已废弃 keep：重判为 discard（有载体）或 sediment |
| 冲突 | <sid8> | 与 <条目/文件> 相反：<一句话> |
| 阻塞 | <sid8> | <reason> |
| 沉淀待核 | <sid8> | 判定 sediment 且已在库外，但无 land 记录 —— 沉淀可能没真落 |
| 未处理 | <sid8> | 尚未判定，结果不完整 |

### ④ 备注
*最多 3 条*

- <人工补充>
````

## 稳定规则

| 项 | 规则 |
|---|---|
| 列数与列名 | 固定，不增不减不改顺序 |
| 内容列 | 取判定的 `value`（kill 取 `evidence.quote`，discard 取 `reason`）；宽 56，按句读截断补 `…`。回答「**这条会话是什么**」 |
| 判定理由不进结果块 | 2026-11-11 移除「为什么」列：判定理由留在 `findings.reason/value/evidence` 与 `report.md`。结果块只回答「是什么、什么状态、凭什么这个状态」，塞判据会把内容列挤扁 |
| 处置 / 处置理由 | **处置在倒数第二，理由紧跟其后**。判定说「知识上该怎么处理」，处置说「库里现在是什么」——两件事，分开写才看得出缺口。**理由只写事实，禁止「与现状一致」这类复述**，且**归档范围不许出现「保留」二字**：<br>· 待删 + kill/discard → `判定该删（discard），待你点头后 purge`<br>· 待删 + sediment → `待沉淀（N 条）后删`；已 land → `沉淀已落（N 个文件），待你点头后 purge`<br>· 待删 + 置顶 → 上述任一 + `｜isPinned=1，一并删（不需先取消置顶）`<br>· 卡住 + blocked → `读取失败未判：<reason 首句>`<br>· 已删 + sediment → `沉淀已落（N 个文件）后才删的`；无 land → `无 land 记录 —— 需核对沉淀是否真落`（同时进 ③「沉淀待核」）<br>· 已删 + kill/discard → `判定 kill 后已 purge`<br>· 保留 + sediment 且 `delete_after=false` → `delete_after=false：原文留作证据（条目已落 N 个文件）`，不许写成「尚未 purge」<br>· 非归档范围仍用 `保留 / 保留(置顶)`，理由照旧 |
| 待删计数 | 第三行写 `已删 N · 待删 M`；归档范围内 `待删` = ① 里所有仍在库的行（`卡住` 不算）。M>0 追加 `｜待你点头后执行沉淀 / 删除`。计数与 ① 同口径：旧版 keep 行不进 ① 也不进计数，只进 ③「旧判定」 |
| keep 的语义 | **归档范围不合法**：`mark` 直接拒收，终态只有删（sediment 后删 / discard 直删）。只有非归档范围（`--scope all`）可以短期挂起，此时必须写 `why_not` + `next_action` |
| 沉淀什么列 | `findings.sediments[*].title`；超过 44 宽先按标题截，无标题退回 `summary`。列宽 60 |
| 宽列排布 | 内容 / 沉淀什么 / 说明三类文本列（`WIDE_COL >= 20`）**不补尾空格、分隔行只写 `---`**；补空格只发生在窄列，为的是源码里竖线能对齐。CJK 记 2 宽 |
| 空集 | ① 无行时写「无」；② 无行时写「无」；③ 全无时写「无」；④ 无备注时写「无」 |
| 表格 | GFM 表格；数字列在分隔行用 `---:` 右对齐；单元格内 `\|` 转义、换行压成空格 |
| 截断 | ① 内容 72 / 处置理由 120、② 沉淀什么 60 / 来源 40、③ 说明 240（显示宽度，CJK 记 2）。**③ 必须放宽**：冲突原文常带「需核对线上实际存值」这类行动指令，60 宽会砍掉 |
| 排序 | ① 判定组序 → 体积降序 → sid；② 条目数降序 → 落点名；③ 置顶待删 → 旧判定 → 冲突 → 阻塞 → 沉淀待核 → 未处理，组内 sid 升序 |
| 摘要换行 | 前三行行尾两个空格（markdown 硬换行），否则渲染器会把三行并成一段 |
| 计数口径 | `条目` 来自 findings；`文件` 来自 `land` 事件；只数实际写出的文件，不数 OV 资源 |
| 处置 | 归档范围由库现状反推：不在库 `已删`；在库且有判定 `待删`；在库且 blocked `卡住`；库读不到 `-`。非归档范围沿用 `保留 / 保留(置顶)` |
| 表头计数 | `已删 / 待删` 与 ① 处置列同一口径；库读不到时两处都写 `-`，不写 `0` |
| 备注 | 硬上限 3 条；超过直接报错退出，不静默丢弃 |
| 正文 | 块外不写任何散文；不加 ```` ``` ```` 围栏；不改写、不重排、不省小节 |

## 逐会话明细（`result --detail` / `detail`）

结果块回答「账目对不对」，明细回答「这条会话到底讲了什么」。**明细接在结果块后面，不替换任何一节。**

````markdown
### ① 会话 · 明细（长文本按列宽截断，全文见 findings/<sid>.json）
*排序：sediment→kill→discard→blocked，组内体积降序；引文列宽随数据自适应*

| sid | 轮 | 判定 | 内容（会话总结） | 依据轮 | 证据引文 | 落点 | 处置 | 处置理由 |
| --- | ---: | --- | --- | --- | --- | --- | --- | --- |
| <8 位> | <n> | <verdict> | <判定 value / kill 的原句 / discard 的 reason> | <2-2 / 3-3> | <最宽的一条 evidence.quote> | <落点> | 已删 / 待删 / 卡住 / - | <宽 240，超出截断> |
````

| 项 | 规则 |
|---|---|
| 内容列 | 宽 96，超出即补 `…`；明细是扫读视图，全文看 `findings/<sid>.json` 或 `report.md` 对应小节 |
| 依据轮 | findings 前三条 `evidence.turns`，` / ` 连接；无 evidence 写 `-` |
| 证据引文 | 取该会话**最长的一条** `evidence.quote`（原句最能说明读了什么）；列宽取所有引文的 80 分位并夹在 `[40, 88]`，随数据自适应，不写死 |
| 未处理 | 明细只列已判定；有 pending 时在表后补一行「未处理 N 条不在明细里：sid…」 |
| 自检 | `detail --check`：明细行数必须等于已判定条数（归档范围不计旧版 keep 行），且每条 sid 都在表里 |
| 输出文件 | `--write` 写 `detail.md` 或 `result-detail.md`（**不覆盖 `result.md`**） |

## 为什么这几条是硬约束

- **固定排序**：不同轮的会话集合本来就在变，如果排序也随人变，diff 会全是噪声。
- **空集写「无」**：省略小节会让「这轮没冲突」和「忘了检查冲突」看起来一样。
- **条目 vs 文件分开**：两者不等就是发生了合并（3 条并成 2 个文件），这是要看的信号，不是错误。
- **处置查库**：不靠对话记忆判断删没删；库是唯一事实。
- **不包围栏**：包了就没有表格，回话在聊天窗里是一坨等宽文本。这一条是 2026-11-11 实际踩到的。
