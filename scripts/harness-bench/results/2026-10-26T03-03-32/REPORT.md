## 结论应怎么读（修正记录）

**这张表是「本机配置下的体检」，不是 harness 的能力排行榜。** 同一次 run 里已经证明，一处本地配置能凭空造出 37% 的差距：

- **codex 是本轮唯一被查出配置缺陷的一家**：原配置把远端插件市场指向 `127.0.0.1:1` 黑洞，握手 502 后重试 6 次，进程启动到真正发出请求空转 9.1s，且每轮都付。加 `--disable apps --disable plugins` 后 S1 16.1s→9.3s、S3 input 17446→9226（其中 8.2k 是插件工具定义）。**表中 codex 全部为改动后数据**，改前的原始结果留在 `codex-before/`。
- 由此「codex 全面最慢」不成立：改前末位、改后中游。**其余各家若存在同类本地配置缺陷，其数字同样偏低，只是没被查出来**——所以跨 harness 的耗时差只能读作「本机现状」，不能读作「harness 天生快慢」。真正属于 harness 自身的，只有协议特性（有无流式帧、是否上报 usage）与自带的 system prompt / 工具规模。
- **codex 不是交错跑的**：其余家按「轮次→harness」轮转，codex 是事后整批重跑，丢了交错设计，带时间与负载 confound。37% 的差距远大于噪声，但几秒级的小差距不可比。
- **每轮耗时都含启动开销**（cloudcli 每轮新起一个 CLI 进程）。实测「turn 开始 → harness 自己记录到用户消息」中位数：pi 197ms、claude 211ms、opencode 390ms、omp 425ms、workbuddy 904ms、**codex 3368ms**（改前 9209ms）；zcode 的 rollout 只覆盖最近会话、dsh 是常驻 ACP 桥，两家无可用探针。也就是说 codex 剩下的 9.3s 里仍有约 1/3 是启动开销，不是模型。
- **workbuddy 的权限模式**：S7 用 `auto`（app 新默认）重测，此前是 `bypassPermissions`。两者的单样本对比互有胜负（同一条编辑任务 auto 19s vs bypass 25.5s；bench 三轮 auto 中位 23.0s vs bypass 17.1s），**方差主导，不要据此判断哪个更快**。确定的只有一件事：`default`/`acceptEdits`/`plan` 在 `-p` 下必然挂死。
- **omp 比 pi 快**：差在推理量（pi 的思考字符是 omp 的 2~4 倍），不是 harness 开销更小；且 pi 的 `--thinking` 在会话日志里恒记为 `off`，其 effort 是否真送到模型没有取得正面证据。
- **开销榜首也被一处口径 bug 改写过**：zcode 的 input 曾把 cache.read 重复计入（44.8k → 22.4k，见「记录口径」）。修正后最省仍是 pi（3.5k）、最贵变成 workbuddy（26.7k），跨度从 12.8 倍降到 **7.6 倍**，zcode 落到第 6。与 codex 同理：先确认数字是 harness 真实注入，再谈优劣。

## 记录口径
- claude 的 transcript 模型名为 `glm-5-3-flash`（anthropic 兼容层命名惯例），即 glm-5.3-flash。
- codex 归一化行无 model 字段，模型以其 transcript turn_context 为准（第 0 步已实证）。
- dsh 无 per-turn 模型旗标，跑批期间 profile 默认模型临时钉为 volcano-ark/glm-5.3-flash。
- token 口径按各 harness 自己的 transcript 用量（取 breakdown.input，即整段 prompt 的大小，含缓存命中），harness 间计法不一：dsh 不上报用量（记 —）；pi / workbuddy 的 3.5k / 26.7k 里未缓存部分只有几十 token，其余都是命中缓存的部分；zcode 的 22.4k 是「3 块 system + 27 个工具定义」的真实 prompt，已按修复后的读取口径还原（见下）。跨 harness 的 token 数只作量级参考。
- zcode 的原始记录曾把 cache.read 重复计入 input（其自身 total 恰为 input+output，input 已含缓存），使 22.4k 的 prompt 被记成 44.8k；本报告已按 `input - cacheRead` 还原，服务端读取器同步修复（bench 目录外的产品修复）。
