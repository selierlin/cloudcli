## 1. 背景：为什么"体感上不知道是干啥的"

当前指示系统的问题不是配色，而是结构。按根因排列：

1. **三种语义共用一个 8px 圆点，靠颜色区分。** 黏性未读、瞬时活动、时间衰减，三种完全不同的生命周期共用一个形状。颜色在这里是**密码**而不是语义。
2. **优先级链 + 互斥 ⇒ 高优先态吞掉低优先态。** 黄点一旦置位不会自动消失，于是绿、紫永久被遮蔽，直到用户点开该会话。信息不是密度低，是被**侵占**。
3. **同一语义在两个页签不一致。** 绿点（最近活跃）只有「项目」页签的会话行有，「对话」页签的行组件根本没有这个维度，永远不画。
4. **图标语言互相打架。** 会话绿点（活跃）、项目行绿✓（TaskMaster 已配置）、黄⭐（收藏）挤在同一片区域，且都是"绿/黄 + 圆"。
5. **"未读"不可信。** 未读只在**实时 WebSocket 事件**里产生，刷新页面即清空；换设备、隔天打开更没有。用户一旦发现它说谎，会整体不信任所有指示。
6. **折叠的项目行不聚合。** 子会话有事等你，项目折起来时项目行**没有任何提示**——恰好在最需要它的时候看不见。
7. **每一个点都要 tooltip 才能懂。** 需要背图例的设计本身就是失败信号。

## 2. 用户实际在问的五个正交问题

| 编号 | 问题 | 生命周期 | 紧急度 |
|---|---|---|---|
| Q1 | 有没有事等我？ | 黏性，处理完才消 | 最高 |
| Q2 | 它现在在动吗？（前台/后台） | 瞬时，跑完即消 | 中 |
| Q3 | 我最近去过哪？ | 时间衰减 | 低 |
| Q4 | 我标了重点吗？ | 用户设定 | 低 |
| Q5 | 哪个项目里埋着事？ | 聚合 | 高 |

现方案把 Q1/Q2/Q3 压成一维。本方案的核心：**一个位置 / 一种形状，只回答一个问题**。

> Q1 的分级（D6）：`permission_request` → **action**（最高紧急）；报错 / 新消息 → **notice**（次级）。Q1 是两者的上位问题，"最高"指 action 档。

## 3. 设计原则（实施与验收的判据）

1. **一种形状只代表一个含义**，含义不靠颜色记。
2. **显著度 = 紧急度**：要你动手 > 在动 > 有新动静 > 最近去过。
3. **黏性态与瞬时态必须形态不同**，不能只换颜色（现状反例：全是圆点）。
4. **跨所有列表一致**；项目行**聚合**其子会话状态。
5. **零 tooltip 可懂**：形状 / 图标 / 字重自解释；tooltip 只作补充。
6. **色盲冗余**：每个颜色都配一个形状或图标差异；**聚合槽没有"加粗"维度时尤其如此**（§4 通道 D）。
7. **最高优先信号永不让位**：不因 hover / 布局挤压而消失（见 §4 通道 B 右缘规则）。

## 4. 目标模型：三段通道 + 项目聚合

一行切成**左 / 中 / 右**三段，位置即语义：

```
┌ 左缘「活动」┬ 厂商 ┬ 标题(未读加粗) + 📌 ┬ 右缘「待处理」+ 时间 ┐
│   ◐ / •      │  🅲  │  修复登录超时…      │     5m · ⚠         │
└─────────────┴──────┴────────────────────┴────────────────────┘
   瞬时 · 会动                                黏性 · 不会动
```

> 右缘顺序以 §通道 B 的栈为准：`… age · 胶囊`（age 在左、胶囊在右）。

### 通道 A — 左缘「活动」（瞬时，唯一允许动的"点"）

| 状态 | 呈现 |
|---|---|
| 前台回合在跑 | 旋转环（spinner，从右缘移来，与"点"同族同位置） |
| 后台 agent/workflow/命令在跑 | 呼吸圆点 |
| **前台与后台同时命中** | **旋转环**（前台优先；后台在 tooltip 里补充说明） |
| **当前选中** | **空**（内容区已可见 ⇒ 通道 A 静默；**现状选中行仍显示 spinner，此为有意变更**，见 §5） |
| 空闲 | 无 |

- 单槽位规则：`activeSessions ∧ backgroundSessionIds` 可同时命中；本方案定 **环优先**。注意这与现状相反——现状是 `isProcessing = active && !background`（后台吞掉前台 spinner），本设计**有意改为环优先**，因为"前台正回合"是更当下的信号。
  - **实施更正（片 1，2026-10-09）**：该组合在当前数据模型下**不可达**——`SessionProtectionContext` 里 `activeSessions` 是"有任意活动"，而 `backgroundSessionIds` 是其**"仅后台"子集**（`isBackgroundOnly = activity.background === true`，每个会话只有一个 `background` 布尔），与"前台在跑"（`active && !background`）**按构造互斥**。实现仍按"环优先"写（先判前台），但它只是**防御性**的：**不产生可见变化，"环优先"不构成行为变更**。§5 该行保留为防御性规格。
- 项目行聚合沿用同一真值表（§5）。

> **删除绿点。** 它要么等于"你刚点过"（你自己知道），要么等于"别人动过它"（已归通道 B）。信息量≈0，却是最大混淆源。

### 通道 B — 右缘「待你处理」（黏性，形状 = 胶囊 / 字重，不是点）

| 状态 | 呈现 |
|---|---|
| 需要你操作（权限请求） | **实心琥珀胶囊 + 图标（⚠/手）** |
| 有新动静（完成 / 新消息） | 标题**加粗** + 极小蓝点 |
| 无 | 无 |

- **一期胶囊不带数字**（见 D7）：`attentionSessions` 只有 `Map<id,level>`，无事件计数/去重来源，per-session 的 `⚠n` 不可信。
- 打开该会话即清；被删除即清（沿用现规则，`clearSessionAttention`）；**被解决/取消也应清**（`permission_resolved` / `permission_cancelled`，见 §6）。
- 胶囊的**形状 + 图标**让它和左缘"点"物理上不可能被混淆。

> **右缘布局规则（解决与 hover 浮现控件的冲突）** —— 现状右缘是"动态让位区"（项目桌面行 `SessionOptions` 绝对定位于 `right-2`、行用 `pr-11` 预留；对话行 `right-1.5` 浮现重命名输入框；age/spinner 靠 `group-hover:opacity-0` 让位）。新规则：
> - 右缘是一条**从左到右的栈**：`[age（可让位）] [胶囊 ⚠（常驻）] [菜单按钮（hover 浮现，槽位固定预留）]`。
> - **胶囊常驻、永不让位、`flex-shrink-0`**：它是最高紧急度信号，hover 时消失即违背 §3 原则 2；也**不允许被菜单按钮遮挡**——菜单槽位由行的 `pr-*` 预留，排在胶囊右侧。
> - 唯二允许被挤压/让位的是 **age**（`truncate` / hover 隐藏）与标题；数字若二期启用则封顶 `9+`。
> - 由此落地：`SessionOptions` 与重命名输入框**不得覆盖胶囊**；两页签必须有同一实现（走 §4 通道 E 的共享组件）。

### 通道 C — 标题区「属性」

- 📌 pin 保留（用户设定，长期）。
- 时间(age) 弱化到右缘：与通道 B 用 `·` 分隔，形如 `5m · ⚠`（age 左、胶囊右）。
- **消息数一期不显示**：`messageCount` 现状恒为 `0`（`server/modules/websocket/services/session-upsert-broadcast.service.ts:50`、`server/modules/projects/services/projects-with-sessions-fetch.service.ts:127`、`useProjectsState.ts:610` 均写 0），无可用数据源 ⇒ 侧栏的 `messageCount > 0` 徽标（`SidebarSessionItem.tsx:243/518`）永不渲染。补计数链路列入二期（§10），否则该槽恒空。
- 未读使标题加粗（`font-normal → font-bold`）会在清除瞬间改变 `truncate` 省略号宽度，产生轻微抖动；长标题场景验收时目测即可——可接受但应知情。

### 通道 D — 项目行「聚合」

项目折叠时把子会话的**最高优先态**聚合到项目行：

| 子会话最高态 | 项目行显示 |
|---|---|
| 有待你操作 | 琥珀胶囊 `⚠`（+ 数字 n） |
| 只有新动静 | **铃铛图标**（notice 形状，非纯色点） |
| 只有后台在跑 | **环 / 齿轮图标**（background 形状，非纯色点） |
| 全空闲 | 无 |

- **形状冗余**（二审 Codex）：项目行没有"加粗"这一冗余维度，若 notice/background 只画蓝点/紫点，去色后无法区分（违反 §3 原则 6）。故二者用**不同图标/形状**；§12.5 增"灰度去色后项目聚合仍可区分"。
- **n 的定义：待处理会话数**（该项目下 attention 为 `action` 的会话个数），**不是**项目总会话数；封顶显示 `9+`。数错会把胶囊变成近乎常亮，聚合信号退化为噪音（违背 §3 原则 2）。
- **数据源与可得性（二审 Codex，重点）**：`Project.sessions` 只是已加载页（`sessionMeta.hasMore` 表明还有未加载会话）；而 `permission_request` 事件、`/api/providers/sessions/running` 返回**都不带 `projectId`**（`server/modules/providers/list/claude/claude-runtime.provider.js:1204` 只含 `{requestId,toolName,input,sessionId,provider}`；running 端点只含 `{sessionId,tasks}`）。因此**纯前端 `sessionId → projectId` 索引**只能从已加载 `Project.sessions` 或 `session_upserted`（后者带 `project.projectId`）学到映射，**覆盖不了深层链接 / 未加载分页 / 纯后台会话**——分页漏算只是从"遍历 sessions"转移到"索引查不到"，且"索引"本身是需生命周期管理的新增状态（upsert / 别名合并 / 删除 / 项目迁移）。**结论：片 2 的聚合正确性依赖源头补 `projectId`（事件或 API）或后端项目级 summary**；否则只能降级为"已感知会话"的不完整聚合，并在 UI 措辞上如实（§13）。
- **D4 默认（已裁定）**：项目**展开后仍保留聚合**（表征"这个项目"而非"某一行"，与 Q5 一致）；仅在批量管理模式隐藏以降噪。

### 通道 E — 跨页签一致性

- 两个页签共用同一套通道。抽取**模块内共享指示器组件**，避免再次分叉——**当前不一致的根因就是两处各写了一遍**。
- 「对话」页签已按时间排序，天然不需要 Q3，删掉绿点后两边**自动一致**。

## 5. 状态矩阵（渲染真值表）

| 会话状态 | 左缘 A | 右缘 B | 标题 | 行背景 |
|---|---|---|---|---|
| 空闲 · 已读 | 空 | 空 | 常规 | 默认 |
| 空闲 · 新动静 | 空 | 小蓝点 | **加粗** | 默认 |
| 空闲 · 待你操作 | 空 | 琥珀胶囊 + ⚠ | **加粗** | 默认 |
| 前台在跑 | 旋转环 | （若有事） | 常规 / 加粗 | 中性 live 底 |
| 后台在跑 | 呼吸点 | （若有事） | 常规 / 加粗 | 默认 |
| **前台在跑 + 后台也在跑** | **旋转环**（环优先） | （若有事） | 常规 / 加粗 | 中性 live 底 |
| 前台在跑 + 待操作 | 旋转环 | 琥珀胶囊 | **加粗** | 中性 live 底 |
| **当前选中 + 前台在跑** | **空（有意变更）** | 空 | 常规 | 选中底 | 
| **当前选中 + 曾有未读** | 空 | 空 | 常规 | 选中底（主色 inset） |
| 当前选中（其余组合） | 空 | 空 | 常规 | 选中底 |
| 已 pin | — | — | + 📌 | — |

要点：
- 通道 A 与通道 B **正交、可并存**（两通道分居左右两端，不再互斥）。
- 行背景**不再随"最近活跃"变绿**；"live"底改为中性色。
- **通道 A 的选中规则**（二审 Claude）：选中会话的内容区已可见 ⇒ 通道 A 静默。**现状选中行的 spinner 仍显示**（右缘 `isProcessing` 分支不带 `!isSelected`，只有左缘点被抑制）；新真值表把选中行的活动指示一并归零，**属有意行为变更**，须在 §11"spinner 归位"同步测试，勿当遗漏。
- **通道 B 与选中——注意这是"丢弃"不是"挂起"**（二审 Claude）："选中行右缘必空"由① 打开即清（§6 `clearSessionAttention`）+ ② 置位时排除当前会话共同保证；但②的实现是**直接 `return`、事件被丢弃**（`useProjectsState.ts:489-492`），`websocket_reconnected` 也不重放补记。后果：你正看着 A 时 A 弹出权限请求 → 不置位 → 你切到 B（权限仍阻塞在 A）→ **A 行永远无胶囊**，直到 A 再产生下一个事件。这是 §1 第 5 条"指示说谎"的**反方向**（该亮不亮），列入 §13，一期可选在"切走"时对原当前会话的 pending 权限补记一次（数据在事件流里有据可查）。

## 6. 交互 / 生命周期规则

| 事件 | 行为 |
|---|---|
| 非当前会话收到事件（非白名单 kind） | 置位右缘 B；`permission_request` → action，**其余（含普通 `error`）→ notice**（见 D6） |
| **非当前会话的 `permission_resolved` / `permission_cancelled`** | **清除该会话右缘 B**（**现状：被忽略、不清除 ⇒ 缺口**，二审 Codex）；同一会话多 `requestId` 时须用**内部 pending 集合**判断"清空 or 保留"，不能只凭一次 resolved 就清 |
| 升级 | notice → action 可升级；action 不回退（沿用现规则，取最强） |
| 打开该会话 | 清除该会话右缘 B（同时它是当前会话，不会再被置位） |
| 切走当前会话 | 可选：对原当前会话补记 pending `permission_request`（§5 缺口，C-3） |
| 删除该会话 | 清除 |
| 前台回合开始 / 结束 | 通道 A 显示 / 隐藏旋转环 |
| 后台任务开始 / 结束 | 通道 A 显示 / 隐藏呼吸点 |
| 前台 + 后台同时命中 | 通道 A 显示旋转环（环优先） |
| hover 一行 | 胶囊常驻不移位；仅 age 让位给菜单（§4 通道 B 右缘规则） |
| 项目行聚合 | 渲染期派生（索引的**可得性与生命周期**见 §4 通道 D，需源头带 `projectId` 或后端 summary） |

**二期收紧（二审 Claude，解决原 §6 与 §12.11 的先后矛盾）：** `session_upserted` 不能无条件点亮 notice（可能只是标题/路径/分页等元数据刷新）。定义唯一"有新内容"白名单、忽略 housekeeping、用事件 ID/序号去重——**这三项随二期落地**（§10），一期按现状；§12.11 的"重连重放去重"相应**移到二期**，避免"一期按现状实现却要求去重单测通过"的自相矛盾。

## 7. 可访问性（色盲冗余 + 动效 + 屏幕阅读器）

| 信号 | 颜色 | 冗余维度 |
|---|---|---|
| 前台在跑 | 中性 | 形状（环）+ 旋转动效 |
| 后台在跑 | 紫 | 形状（点/环）+ 呼吸动效 |
| 待你操作 | 琥珀 | 形状（胶囊）+ 图标 ⚠ |
| 新动静 | 蓝 | 字重（标题加粗）+ 点 |

- **色盲**：任一信号去掉颜色后仍可区分；**项目聚合槽无加粗维度，必须靠形状冗余**（§4 通道 D）。
- **动效降级**（一审 Claude）：所有指示动效加 `motion-reduce:animate-none`（静态形状与颜色语义保留）。现状 `animate-pulse` / `animate-spin` 未接（仅 bottom-sheet 有），本次一并补。
- **屏幕阅读器**（一审 Codex）：补 **row-level 可访问摘要**（组合 A/B/C 状态），状态**转移时**经 `aria-live="polite"` 播报（非每次渲染）；装饰性重复 marker 设 `aria-hidden`；项目聚合读出"n 个会话待处理"。两页签 + 折叠/展开读出的语义须一致。

**已裁定（D1–D4、D6、D7）**

- **D3 项目行聚合：做。** 这是"体感不知道干啥"的最大来源（**前置：源头 projectId / 后端 summary，见 §4 通道 D**）。

- **D6 `error` 归 notice（降级）。** 一期 action **只留 `permission_request`**（明确阻塞、等用户动手）；普通 `error` 归 notice。理由：现状 `getAttentionLevel` 把所有 `error` 归 action，但 action 定义为"处理完才消"、实现却是"打开即清"，实际语义是"未读错误"而非"待你操作"，会持续误导。**这是一次行为变更**：`getAttentionLevel` 需改（`error` 从 action → notice），受影响测试须同步。根治（区分阻塞错误 vs 命令/传输/工具失败）需引入 `requiresAction / blocking` 来源字段，列为后续。
- **D7 胶囊一期不带数字。** `attentionSessions` 只有 `Map<id,level>`，无事件计数/去重来源，per-session `⚠n` 不可信 ⇒ 一期只保留图标/胶囊。项目聚合的数字 n 用**待处理会话数**（可算）保留、封顶 `9+`。

**待确认**
- **D5（二期）**：未读**持久化**——见 §10。

**一条对审阅的反驳（引证已于二审更正）**
- Claude 批注 3 建议"四类状态色收敛到语义 token"。**本方案不采纳**——但**并非**因"某文档里的用户裁定"：经二审复核，`docs/research/CloudCLI浅色表面跟随主题方案.md` 中**并无**状态色固定结论，我此前对该文档的引证有误（已改）。真实依据有两条：

## 10. 分期

### 一期（本方案主体）：视觉与语义重构
- 片 1：通道重构。删绿点；左缘只留活动（前台环 / 后台点）；右缘未读改胶囊 / 加粗；行背景去绿；抽取模块内共享指示器组件；两页签统一。
- 片 2：项目行聚合（含折叠态与展开态）。**前置（二审 Codex）**：聚合正确性依赖 attention/background 状态在**源头携带 `projectId`**（事件或 API）或后端项目级 summary；否则只能做"已感知会话"的不完整聚合。可选：切走时补记 pending 权限（§5 缺口）。
- 片 3：清视觉噪音。**`TaskIndicator` 定案**（见下行）＋补空态/图例文案。

### 二期（另立，已展开为独立需求文档：[`CloudCLI侧边栏状态指示重设计-二期需求.md`](CloudCLI侧边栏状态指示重设计-二期需求.md)）

> 二期解决的是**「指示说的是真话」**（数据源与生命周期），一期解决的是「看得懂」。四条要点已在二期文档里展开为「问题 / 真源 / 缺口 / 选项 / 验收判据 / 前置」，并补出**共享前置 P-1**（runtime 枚举未决审批 + `/running` 补 `projectId`）与**一处提法更正**（「重连重放去重」实为「假未读治理」——网关事件不重放，重连是全量重取）。

- **未读持久化**（D5）：现状内存态、刷新即空、跨设备不一致，需服务端 `last_seen` / unread 标记。**在视觉与语义理顺之前不做**。二期文档落点＝**B-4 同构新表 + REST**（形如 `session_drafts` 的 per-user-per-session 表；`user_preferences`／B-3 已被二审 T1 否），且**与「假未读治理」（D-1）同批**——共用 D-1 顺带产出的内容指纹（T2：批次 2 由三步压两步）。
- **`action` 态的加载时重建**（片 1 验收新发现，2026-10-09）：`attentionSessions` 是内存态、**刷新即空**（`HEAD` 亦然，非片 1 引入）。对 `notice` 只是少看一条动态；对 `action`（正阻塞的权限请求）会让"哪个会话卡着等我"彻底无痕——与 §1 第 5 条"指示说谎"同类。需在挂载/刷新时从服务端未决审批重建 `action`；**前置**：服务端只有 `getPendingApprovalsForSession(sessionId)`（经 `chat.subscribe` **按会话**下发，`claude-runtime.provider.js:1690`），**无"批量列出未决审批"端点**，故需新增端点或扩 `/running` API。与 D5 同批（都依赖服务端状态）。**同时收 C-3 缺口**：切走当前会话时对原会话补记 pending 权限（§5、§6）。**（2026-10-10 已实施＝二期批次 1：选定「扩 `/running` 旁挂 `pendingPermissions`」，C-3 两侧都落，见二期文档 §2.4。）**
- **`messageCount` 计数链路**（二审 Codex）：补服务端真实计数与事件更新，否则消息数槽恒空（§4 通道 C）。
- **`session_upserted` 白名单收紧 + 重连重放去重**（二审 Claude）：见 §6。

## 12. 验收判据

1. **零图例测试**：不读 tooltip，仅看一行，能判断"它有没有事等我 / 在不在动"。
2. **并存测试**：一条会话可同时呈现"左缘活动 + 右缘未读"，互不遮蔽。
3. **页签一致**：同一会话在「项目」「对话」两页签的状态呈现一致（对话页签可无"最近去过"，但有、也只因态而不同；**选中 + 前台在跑为有意变更**，见 §5）。
4. **折叠可见**：项目折叠 + 子会话有待操作时，项目行给出聚合提示。
5. **色盲测试**：去色后四类信号仍可区分；**灰度去色后项目聚合（notice vs background）仍可区分**（形状冗余，二审 Codex）。
6. **回归**：`vitest run src/modules/sidebar`、`npm run test:client`、`npm run typecheck`、`npm run lint`、`npm run build:client` 全绿。
7. **人工场景**：`?indicator-demo=1` 逐场景过一遍，与 §5 真值表逐格对齐。
8. **布局变体**（一审 Claude）：桌面 / compact / 移动视口各过一遍 §5 真值表；重点核验左缘悬挂点（`-translate-x-1`）在卡片 `mx-3` 不被裁剪。（侧栏折叠图标栏不在范围。）
9. **主题**：light / dark + 用户自定义主题各过一遍（状态色为固定色——验证中性部分与令牌一致、状态色不被主题穿透导致不可读）。
10. **动效降级**：系统"减少动态效果"时环/点静态呈现、语义不丢（`motion-reduce`）。
11. **状态机单测**：`markSessionAttention` 的事件分类、notice→action 升级且 action 不回退、打开/删除清除、当前会话抑制、**`permission_resolved`/`permission_cancelled` 清除（单/多 `requestId`）**。（**重连重放去重、upsert 白名单收紧、分页聚合不漏**依赖二期/源头 projectId，移至二期。）
12. **TaskIndicator 五态**（片 3）：配置正常 / 仅 TaskMaster / 仅 MCP / 未配置 / **error**（error 不得再伪装为"未配置"）。
