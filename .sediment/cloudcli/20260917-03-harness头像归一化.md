## 决策与理由
- 根因不是"没拉满"，而是尺寸写死（图标占 chip 60%）+ 8 份资产形状差异大
- 资产层修（viewBox / 裁透明边）优先于逐屏布局 hack → 改一次全局生效
- 宽高比类差异（dsh / cursor）→ 接受 letterbox，不拉伸、不给单个 provider 特判盒子
- 不给 LLMProviderLogo 加 size prop、不写资产规范文档 → 避免过早抽象
- chip 底色 → 直接去掉而非调淡：多数标记自带满格方块，底色构成第二层框
- 图标 14 → 16 而非 18/20：16 是标准级距 h-4 且与复选框同尺寸；20 在 36px 行动里压过标题
- 交付 → 只提交不部署：工作区混着 47 个未提交 WIP（dsh provider/quota/i18n/ADR）

## 踩坑 / 注意点
- 我误判 workbuddy.svg "资产坏了"（图形出血到画布外）→ 从 git 取回旧 png 逐像素比对发现是同一构图，png 只多了 10% 安全边距、出血在 png 里同样被裁，属品牌设计本意。判资产坏之前先取上一版比对
- 只看"图标占 chip 比例"（12/20=60% → 14/24=58%）→ 环从 4px 变 5px，且没算 chip 底色本身构成第二层框，改完亮反而更觉得"有边界框"。容器底色是可见造型，不只是布局
- 曾以为"给 viewBox 补白能让图形变大"→ 错，缩放比例由 artwork 宽高比决定；对 cursor 收紧 viewBox 数学上是 no-op
- Tailwind v3.4 无 4.5 级距，18px 只能写 h-[18px]
- 本地 vite dev server 504 Outdated Optimize Dep 会让前端卡在 splash，与改动无关；探针测到 logoSampleCount 0 别当成自己引入的 bug
- 环境事实：:3001 供 dist 但需登录，无法免密截图验证侧边栏
