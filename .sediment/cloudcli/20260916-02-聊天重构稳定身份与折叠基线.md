## 决策与理由
- WorkBuddy 只作为行为参考，不复制其事件模型 → 多 provider 的事实能力不同。
- Provider adapter 提供事实，统一投影层生成 Turn/Segment → UI 不按 provider 名称分叉。
- 用户 disclosure ownership 优先 → 流式更新、分页和懒卸载不得覆盖用户选择。
- 所有 Answer Segment 保持可见 → 不再把最后一段正文当作唯一答案。
- 每阶段 gate 通过后再进入下一阶段 → 隔离身份、投影、分页和窗口化风险。

## 踩坑 / 注意点
- NormalizedMessage.id 原先未进入 ChatMessage，key 会随内容前 48 字变化并反复 remount。
- finalize 与 persisted refresh 使用不同 store id，必须以独立 segmentId 保持 UI 身份。
- Reasoning 与 ExecutionProcess 原先会对同一内容执行两套自动折叠。
- 连续工具组可能混合成功与失败工具，不能直接默认折叠含 attention 的组。
- WorkBuddy 原生窗口无法由当前无障碍自动化接口读取，实机验证需要人工协助。
