## 决策与理由
- 严重问题先亲自复现再修 → 复核代理结论，避免照单全收。
- 修复取最小面：服务端在校验层拒绝非法 cursor 形态；客户端只改身份来源与窗口步进，
  不动相邻逻辑。
- 前端四阶段合成一个提交 → executionProcess.ts / ChatMessagesPane.tsx /
  useSessionStore.ts 被多阶段反复改写，hunk 级拆分会产生不可编译的中间态。
- src/shared/types.ts 按 hunk 归属拆分：分页协议类型进服务端提交，投影类型进前端提交。
- 提交前用 detached worktree + node_modules 软链验证中间提交能独立 typecheck。

## 踩坑 / 注意点
- decodeCursor 只校验 boundary > snapshotTotal，direction='newer' 且
  boundary===snapshotTotal 时会越界读 snapshotMessages[start] → TypeError 500；
  服务端永不签发该形态，但 snapshotVersion 明文返回，客户端可伪造触发。
- 渲染行 id 一旦回退 provider id，Codex 每次读取重建 id 会让尾部刷新 remount，
  高度缓存与 disclosure 一并失效。
- 视觉窗口是尾部切片，Turn 页行数由字节预算决定，固定 +20 步进会让窗口持续落后于
  已加载内容，中段滚不到。
- 本机 iconv 对合法 UTF-8 报 "Inappropriate ioctl for device"，全仓扫描出现 5 个假阳性；
  Python 解码 + git diff --check 才可靠。
