## 背景
- 用户反馈移动端/H5 聊天界面：点输入框键盘弹起时消息列表不动，底部消息被裁掉。讨论交互方案后落地实现，并连带修了两个衍生 bug。

## 进展
- [x] 统一补偿方案：新增 `useBottomEdgeResizeCompensation` hook（ResizeObserver 于 paint 前监听消息容器，高度变化 Δ 即补偿 scrollTop，缩 +=/涨 -=；零高度跃迁与初始观察跳过）
- [x] 接入 `ChatMessagesPane.tsx:215`，贴底/翻历史场景相对位置均保持
- [x] 键盘动画：外壳 `bottom` 挂 `transition-[bottom] duration-[250ms] ease-out`，零 JS 改动（ResizeObserver 逐帧补偿天然同步）
- [x] Bug1（H5 切会话键盘闪现）：`--keyboard-height` 毛刺 → 上升沿 100ms 防抖提交、下降沿立即提交
- [x] Bug2（原生壳切会话键盘真实弹出）：WKWebView 键盘收起不释放焦点 → `keyboardWillHide` 时 blur 残留可编辑元素
- [x] 验证：582/582 测试、typecheck、oxlint、build 全绿

## 决策与理由
- 翻历史时也跟随上移 → 统一补偿替代"贴底/翻历史"两档 → 一致心智模型："输入框永远紧贴内容"，可预测性优先
- 动画挂外壳 bottom 过渡而非 JS 驱动 → 容器高度逐帧变化，已有 ResizeObserver 补偿自动逐帧同步，JS 零改动
- 防抖只对高度上升沿 → 收键盘必须跟手；毛刺只在异步对账的上升读数出现

## 踩坑 / 注意点
- iOS 键盘收起后 `innerHeight` 与 `visualViewport.height` 异步对账 → 布局变动瞬间算出假键盘高度 → 上升沿防抖规避
- WKWebView 键盘收起后 focus 残留在 textarea → 后续 tap 重新唤起键盘 → 收起即 blur，副作用：收键盘后需再点一次输入框（与 Safari 原生一致）
- 动画过渡使 1-2 帧毛刺被放大成完整"弹出收起"动画 → 隐性 bug 被动画显性化
- 仓库存在**非本次**的未提交改动（翻页锁/上滚意图检测，`useChatSessionState.ts` + `transcriptScrollOwnership.test.tsx`）→ 提交时需区分两批
