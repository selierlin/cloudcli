## 背景
- 聊天页将正文、思考和工具折叠后，展开过程会让 harness 头像消失、移位或重复出现。
- 真机截图确认：工具组展开路径会额外渲染第二个头像。

## 进展
- [x] 确认最终层级：唯一头像与名称 → 可点击执行过程摘要 → 过程内容。
- [x] 过程容器 `ExecutionProcessSummary` 始终渲染唯一身份头，摘要仅负责展开/收起。
- [x] 过程内普通 assistant 行抑制重复身份头。
- [x] 工具组 `ToolGroupContainer` 继承相同标记，修复工具展开时的第二个头像。
- [x] 新增工具组展开不重复身份头的回归测试。
- [x] 定向测试、类型检查、前端生产构建通过。
- [ ] 用真实移动端长任务复核展开、折叠、异常工具和吸顶摘要的视觉结果。

## 决策与理由
- 每个含执行过程的 assistant 回合只显示一个 harness 身份头 → 避免展开状态改变层级或出现重复头像。
- 仅执行过程摘要可点击 → 头像仅表达身份，避免误触。
- 过程内异常/授权项继续露出，只有摘要吸顶 → 保留可处理性并减少手机视口占用。

## 踩坑 / 注意点
- 初版只向普通 `MessageComponent` 传递隐藏标记，工具组展开会重新挂载其内部消息，导致重复头像。
- 隐藏条件一度误加到用户消息头像分支；回归测试定位后已改到左侧 assistant 身份头分支。
- 工作区还包含其他未提交的 provider、快捷回复等 WIP；本沉淀仅覆盖聊天过程身份头改动。
