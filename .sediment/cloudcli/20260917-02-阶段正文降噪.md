# [cloudcli] 单 Turn 统一执行过程

## 背景
- WorkBuddy 长任务会产生大量阶段正文、思考和工具调用。
- 将每个阶段独立折叠后，页面仍会形成密集的“执行过程”入口墙。
- 目标是保留完整过程，同时建立以过程文本为主干的稳定阅读层级。

## 进展
- [x] 每个 assistant Turn 最多生成一个普通 Process Run。
- [x] 最右侧正文保留为暂定或最终 Answer，更早正文归类为 Phase Narration。
- [x] 推理、阶段正文、进度和工具调用按原始顺序进入 Process Run。
- [x] Process Run 默认折叠，不再保留独立 Process Stage。
- [x] 打开 Process Run 后，Phase Narration 完整直显，构成过程文本主干。
- [x] 每段思考保留原始时间位置并默认折叠，实时思考也不自动展开。
- [x] 每个工具批次默认折叠，单次工具调用同样折叠。
- [x] 思考和工具的用户展开状态在当前会话内跨外层卸载保留。
- [x] 搜索只临时展开命中的思考或工具批次，不覆盖用户状态。
- [x] Attention、权限请求和失败在父过程折叠时仍直接可见。
- [x] 折叠 Process Run 时卸载昂贵子树，但保留时间戳定位节点。
- [x] ADR 0003 和领域词汇已更新。
- [x] 前端 620 项测试、类型检查、构建和 lint 通过。
- [ ] 部署后在手机上验证真实 WorkBuddy 长任务。
- [ ] 阶段正文与最终正文重复问题继续暂缓，等待具体样本。

## 决策与理由
- Turn 级单一 Process Run → 避免相似入口形成新的视觉噪声。
- Phase Narration 直接显示 → 用户打开过程时主要想了解执行进展。
- Reasoning 和 Tool Activity 默认折叠 → 它们是按需查看的底层证据。
- 不截断过程文本 → 用户已经主动进入过程层，不再增加第三层交互。
- 不按文本去重 → 相同文本可能具有不同阶段语义。
- Attention 绕过折叠 → 需要用户处理的内容不能隐藏。

## 踩坑 / 注意点
- 仅合并外层入口不够；内层思考如果直接铺开，长任务仍会占满页面。
- 工具折叠原本是组件局部状态，外层卸载会导致用户选择丢失。
- 搜索展开必须是临时覆盖，不能夺取用户的 Disclosure Ownership。
- 分页前后 Process Run 身份必须稳定，避免状态丢失和闪烁。
