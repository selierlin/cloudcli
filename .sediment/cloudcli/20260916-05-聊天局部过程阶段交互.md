## 背景
- 将 CloudCLI 多 harness 聊天体验改造成接近 WorkBuddy、但保持 provider 无关的 Turn/Segment 展示。
- session-sediment:cloudcli

## 进展
- [x] 以可见 Answer 为边界，将一个 Turn 拆成多个独立过程阶段。
- [x] 阶段内按时间顺序统一展示 reasoning、tool、progress，不再嵌套独立 Thought 折叠。
- [x] 阶段摘要区分“思考过程”和“执行过程”，执行阶段显示工具数量。
- [x] 历史完成阶段默认收起；活动、异常和等待交互阶段保持展开。
- [x] 正文稳定 800ms 后自动收起前序阶段，向上阅读时暂停，收起沿用滚动补偿。
- [x] 用户展开权跨流式更新、分页、懒加载和会话切换保留。
- [x] 搜索命中只展开目标阶段，并展开包含目标工具的合并工具组。
- [x] 分页截断阶段显示“较早记录未加载”，稳定 Answer 锚点避免状态重置。
- [x] 导出保持完整内容，不受屏幕折叠状态影响。
- [x] 前端 612 个测试、类型检查、lint、生产构建全部通过。
- [ ] 部署后用真实长会话和手机页面验证视觉效果及滚动手感。
- [ ] 阶段正文与最终正文相同的去重问题暂缓，等待真实样本。

## 决策与理由
- Answer 即阶段边界 → 避免一个按钮展开整轮所有工具。
- 阶段局部折叠、互不排他 → 保留多阶段并行阅读能力。
- 用户操作优先于程序默认 → 防止流式更新和分页擅自改回折叠状态。
- 不做字符串去重 → 当前缺少可靠语义依据，避免误删合法重复正文。

## 踩坑 / 注意点
- 测试环境默认隐藏 thinking，过程阶段 DOM 测试必须显式启用 showThinking。
- 搜索目标可能位于合并工具组第二项以后，必须同时展开阶段和工具组。
- 完成状态不能立即收起，否则正文交接时会闪现和产生高度跳变。
- 生产构建仍有既存 CSS 语法及大 chunk 警告，不由本轮引入。
